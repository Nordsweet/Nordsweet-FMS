# FPL / Charts

The Charts tab in Fly ports chart-browser.html into typed React components. It shares the active flight, bearer authentication, airport picker, NordChart procedure geometry and taxi route calculation with the rest of FMS. Each pane has one thin airport/document toolbar. Its ellipsis popover holds source/category/stage controls, source dates, taxi settings and local PDF import; expired official sheets also retain a visible warning icon. Page navigation, zoom and fit float over the bottom of the sheet. Local PDFs (including user-supplied Jeppesen charts) remain local to the open browser.

Airport details use the same document catalog. Choosing a chart closes the airport popup and opens that document in FPL / Charts; from the standalone Map screen it also navigates to Fly. The destination uses the arrival pane, while the departure and other airports use the left pane. Repeated selections restore the requested sheet even after manually choosing another document. Panel and selection state are transient and are not stored in the flight plan.

The collector is the authority for Polish AIP IFR/VFR/MIL packages: see its docs/API.md, Polish airport charts. The frontend never scrapes PANSA. Airport assignment comes from the publication chapter, and chart categories from its published title; the old static AD-number mapping is ambiguous after the 2025 numbering changes. Existing curated airport records are preserved when the catalog adds missing published airport positions.

Official sheets retain their volume, source URL and effective UTC dates. An offline expired package is visibly marked. Library sheets retain their own PDF revision and calibration. Calibration is applied only to the corresponding library PDF and its configured frame aspect ratio, never automatically to a new AIP edition or an uploaded local file. Missing taxi geometry is left undrawn; the legacy fallback inventing a direct taxi connection is intentionally omitted.

PDF.js renders authenticated bytes inside the app, including on iPad. Its matching fonts, CMaps, ICC profiles and image decoders are bundled and precached locally; no CDN is required. PDF blobs use a dedicated structured-clone IndexedDB cache, excluded from the JSON query persister, and are not retained forever in an in-memory cache. Opened PDFs remain readable offline after reload. A device storage failure does not prevent online viewing. Server-side bulk download does not automatically download every PDF onto every device.

The PDF viewer redraws the visible viewport from the original PDF at the current zoom and actual device pixel ratio. It no longer caps density at 2× or rasterizes a whole fitted sheet under an 8-megapixel ceiling. Canvas memory follows the visible pane rather than the entire enlarged page. While a new render is pending, the previous image provides immediate pan/zoom feedback; cancelled renders cannot replace a newer view. Calibration overlays use the same centered frame and camera transform. Vector details remain sharp at zoom; embedded images retain the detail available in their original source.

The original TAXI/PROC rail tool remains available. FPL row actions and vertical profile retain the same flight state when using the FPL tab. Tests cover official/library separation, runway-grouped generated procedures, calibrated taxi geometry, authentication, UTC expiry, partial initial imports, two independent multipage views, a real PANSA PDF, offline reload and iPad bounds.
